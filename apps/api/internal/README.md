# API boundaries

One modular-monolith process. HTTP parsing/response concerns live in transport/http;
services enforce use-case rules, and persistence adapters execute SQL.

The foundation contains only the health service and PostgreSQL pool. Auth/queue
modules are not implemented. Add their handler/service/repository code under their
own modules when those contracts are authorized. A service must pass one transaction
handle through every repository call in an atomic business operation; repositories
must never commit parts of a use case independently.

`internal/db` is generated by sqlc from `db/queries` and the schema. Do not edit
generated files. Domain migrations, seed accounts and authentication are later S1 work.
